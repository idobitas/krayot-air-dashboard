# krayot-air-dashboard

דאשבורד איכות אוויר לקריות ומפרץ חיפה, מתעדכן אוטומטית מ-[air.sviva.gov.il](https://air.sviva.gov.il).

**אתר חי:** https://idobitas.github.io/krayot-air-dashboard/

## איך זה עובד

```
GitHub Action (workflow_dispatch כל 10 דקות מ-cron-job.org; cron של GitHub כגיבוי)
  └─ scripts/fetch_sviva.py   (py-air-sviva-api)
       ├─ live_krayot.json        נתונים עדכניים: last5m / last30m / history24h / daily30d / metrics
       └─ data/history_90d.json   ארכיון שעתי מתגלגל של 90 יום
  └─ commit + push רק אם הקבצים השתנו
index.html  (GitHub Pages)  טוען את שני הקבצים בעליית הדף וכל 10 דקות
```

| `scripts/fetch_sviva.py` | משיכה, המרת יחידות, צבירת היסטוריה. `--backfill` מושך מחדש 90 יום מלאים |

## נתוני אמת בלבד

הדף מציג רק את 6 התחנות שיש להן הזנה, ובכל תחנה רק מזהמים שהיא באמת מודדת לפי `live_krayot.json`. נתוני ההדגמה של 2017 הוסרו. סיכומי החריגה מחושבים מ-30 הימים האחרונים. תחנה שנכשלה בריצה שומרת את הרשומה הקודמת שלה, עם `stale: true`.

## יחידות

- גזים מומרים מ-ppb ל-µg/m³ **רק** אם ה-API החזיר ppb (ברוב המקרים הוא כבר מחזיר µg/m³). נוסחה: `ppb × משקל מולקולרי / 24.45`.
- **CO נשמר ב-ppm** בכל הפלטים (`last30m.CO`, ההיסטוריה): `mg/m³ / 1.145`. הדאשבורד (חתימת שריפות פיראטיות) מצפה ל-ppm. בתחנות הקריות הנוכחיות אין ערוץ CO, ולכן הערך ריק.
- רוח: `windDir` במעלות (ממוצע מעגלי), `windSpeed` ב-m/s.
- **שעון:** חותמות הזמן מה-API הן `+02:00` קבוע (שעון חורף כל השנה, בלי מעבר לשעון קיץ). בקיץ השעה המקומית היא החותמת + שעה. זה נכון ולא באג; האלגוריתם ממיר ל-`Asia/Jerusalem` לצורך "לילה". הסקריפט מבקש מה-API תמיד תאריכים לפי שעון ישראל (`today_il()`): הספרייה משתמשת ב-`date.today()` של השרת (UTC), ולכן בין חצות ל-02:00 הנתונים נתקעו ב-23:55 של היום הקודם.

## ארכיון ההיסטוריה המתגלגל (`data/history_90d.json`)

- שורה אחת לכל שעה שלמה לכל תחנה (שעה שעדיין רצה לא נשמרת), בפורמט שורה-לשורה כדי שה-diff ב-git יישאר קטן.
- בכל ריצה השעות החדשות נוספות ללא כפילויות לפי `t` (ערך טרי גובר), והחלון נחתך ל-90 יום אחורה מהשורה האחרונה.
- ה-API מחזיר 90 יום אחורה בקריאה אחת. אם חסרות יותר מ-5 ימים בארכיון (קובץ חדש או נמחק), הסקריפט מבצע backfill אוטומטי.
- `updated` בארכיון הוא חותמת השעה האחרונה, כך שהקובץ משתנה (ונעשה commit) פעם בשעה ולא בכל 10 דקות.
- מתוך הארכיון מחושבים: `metrics.*.monthly` (ממוצע 30 יום, רק אם יש לפחות 360 שעות; מסומן `monthlyReal: true`) ו-`daily30d` (ממוצע יומי, רק לימים עם 12 שעות לפחות).
- **ארכיון חודשי:** בכל ריצה כל השורות מהקובץ נכתבות גם ל-`data/archive_YYYY_MM.json` (לפי החודש בחותמת `+02:00`). הקבצים רק גדלים, כך ששעות שיוצאות מחלון 90 הימים נשמרות. קובץ חודש נכתב מחדש רק אם התוכן שלו השתנה. `data/archives_index.json` מפרט לכל חודש טווח ומספר שעות. בדף נטענים בהתחלה רק `live_krayot.json` ו-`history_90d.json`; האינדקס נטען בלחיצה ראשונה על בורר "חודש מהארכיון", וקובץ החודש רק כשבוחרים אותו.
- פרמטר בלי נתון חודשי אמיתי נשאר עם ערך הבסיס ההיסטורי שבדאשבורד ומסומן "בסיס היסטורי".

## הרצה מקומית

```bash
pip install git+https://github.com/GuyKh/py-air-sviva-api.git@6e8bd65315910ef12019ac6798fa417cf5148118   # לא ב-PyPI; אותו commit כמו ב-Action
python scripts/fetch_sviva.py            # רגיל
python scripts/fetch_sviva.py --backfill # משיכת 90 יום מחדש
python -m http.server 8000               # ואז http://localhost:8000
```

דורש Python 3.11+.

## גלאי השריפות (v2b)

במסך הראשי מוצגת שורה תחתונה פשוטה לציבור: 🔥 חשד לשריפה, 🌫️ ייתכן עשן (כולל "גל עשן רחב מהמזרח"), 🏜️ אובך, 🌁 אינוורסיה (אוויר עומד) או 🟢 אין חריגה. 🟢 מוצג רק כשהערכים החיים בתוך יעדי WHO 2021 ליממה (PM2.5 15, PM10 45, NO₂ 25). אחרת השורה כתומה, ואדומה מעל התקן היממתי החוקי, עם הערך והתחנה. גרף השוואת הבנזן הוסר. הציון מחושב בדפדפן מתוך הארכיון השעתי של 5 תחנות ה-PM. כפתור "סרוק 30 יום אמיתיים" בלשונית החיבור מציג את האירועים של התחנה הנבחרת. פירוט: [`docs/fire-detector-analysis.md`](docs/fire-detector-analysis.md).
